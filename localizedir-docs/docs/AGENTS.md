# AGENTS.md — working on the localizedir documentation site

This is the standalone Astro Starlight documentation codebase for [elcoosp/localizedir](https://github.com/elcoosp/localizedir), a Rust proc-macro crate. It documents the crate; it does not contain the crate.

## Stack

- **Astro 7.4.x + @astrojs/starlight 0.42.x** — floors; do not ship lower.
- **TypeScript 6.0.3 (pinned)** — `astro check` does not support TypeScript 7. See `docs/decisions/0001-typescript-version.md`.
- **pnpm** is the package manager of record. No npm/yarn lockfiles.
- Plugins: `starlight-links-validator` (build fails on broken internal links), `starlight-image-zoom`. Rationale for every other plugin's absence: `docs/decisions/0006-plugin-selection.md`.

## Commands

```bash
pnpm install
pnpm dev       # local dev server
pnpm build     # astro build + llms.txt/llms-full.txt generation
pnpm check     # astro sync + tsc --noEmit (0 errors / 0 warnings required — see docs/decisions/0007-check-tooling.md)
pnpm lint      # markdownlint-cli2 over src/content/docs
pnpm qa        # Playwright screenshots: every route × 2 viewports × 2 themes (needs a running `pnpm preview`)
./scripts/check-warnings.sh .qa/build.log   # zero-warning gate (one allowlisted Starlight 404 line — ADR 0005)
```

> Warning-gate note: `pnpm build` emits exactly one allowlisted `[WARN]` — Starlight's
> documented custom-404 recipe (`src/content/docs/404.md`) triggers Astro's route-priority
> warning. `scripts/check-warnings.sh` filters that exact line and fails on anything else
> (docs/decisions/0005-known-warnings.md).

## Content architecture (Diátaxis — one type per page)

| Type | Folder | Frontmatter `type` |
| :--- | :--- | :--- |
| Tutorial | `src/content/docs/tutorials/` | `tutorial` |
| How-to | `src/content/docs/guides/` | `how-to` |
| Reference | `src/content/docs/reference/` | `reference` |
| Explanation | `src/content/docs/explanation/` | `explanation` |

Rules that hold across the whole site:

- Every page has `title`, `description`, and `type` frontmatter; the `type` enum lives in `src/content.config.ts`.
- Second person, present tense, active voice, imperative instructions. Never "simply", "just", "easy", "obviously".
- Every fenced code block declares a language (Shiki via Expressive Code — do not add another highlighter; `docs/decisions/0003-syntax-highlighter.md`).
- Accuracy comes from the source repository, never from invention. Feature claims must trace to `localizedir/src/lib.rs`, `localizedir-macros/src/{args,naming,discovery,expand}.rs`, or the repository README.
- Sidebar order is explicit in `astro.config.mjs`; new pages must be added there.
- `internal-links`: `starlight-links-validator` fails the build on any broken internal link.

## Branding

- Logo: `src/assets/logo.png` (256px derivative of the repository's `docs/logo.png`) + `public/favicon.png`, generated by `scripts/gen-assets.mjs`. Regenerate from the source repo's original; never upscale the derivatives.
- Accent: golden amber derived from the logo (`#f0c010`), WCAG-AA verified in both themes in `src/styles/custom.css` (computed by `/home/z/my-project/scripts/contrast.py` at design time). Do not revert to Starlight default blue.

## QA

`pnpm qa` exits non-zero on console errors, page errors, HTTP ≥ 400, horizontal overflow, missing/duplicate `<h1>`, near-empty `<main>`, theme-application failures, or broken images. Screenshots go to `.qa/screenshots/` (gitignored, not shipped). The manual eyeball checklist and its per-route outcomes live in `docs/qa-report.md`. Re-run the full gate after any config/CSS/logo/content change, immediately before packaging.

## Release notes

- Document every non-obvious decision (versions, assets, highlighting, QA, plugins, warnings) as an ADR in `docs/decisions/`.
- `scripts/build-llms.mjs` regenerates `llms.txt` / `llms-full.txt` on every build; keep its page order in sync with the sidebar when pages are added.
