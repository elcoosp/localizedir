`localizedir` turns an enum into locale-aware accessors over directories embedded with [include_dir](https://crates.io/crates/include_dir). You annotate an enum, the macro embeds your localized directory tree once at compile time, and every lookup afterwards is a cheap navigation inside that tree — no runtime file I/O, no boilerplate.

<Code lang="rust" code={`use localizedir::{LocalizeDir, localizedir};

#[localizedir("tests/fixtures/localized")]
enum AuthDirs {
    Welcome,
    ForgotPassword,
}

let dir = AuthDirs::Welcome.to_localized_dir("fr");
assert!(dir.get_file("fr/auth/welcome/note.txt").is_some());`} />

Locales are discovered from the filesystem at compile time. Typos in the directory structure fail the build with an error pointing at the offending token; unknown locales at runtime return `Option` instead of a file-not-found surprise.

## Why localizedir

- **One embed, many lookups** — the whole base directory is embedded a single time through one `include_dir!` expansion, so compile times stay flat as your template tree grows.
- **Compile-time safety** — missing base paths, missing `(locale, variant)` directories, duplicate directory names, and malformed attributes all fail to compile, at the right source location.
- **Non-panicking core** — `try_to_localized_dir` returns `Option`; the panicking `to_localized_dir` layers an optional `fallback` locale on top.
- **Workspace-proof paths** — relative base paths anchor at `$CARGO_MANIFEST_DIR`, and `$VAR` interpolation matches `include_dir!`'s own semantics.
- **IDE friendly** — generated code is plain, documented, and fully navigable with rust-analyzer.

<Aside type="note">
localizedir requires Rust 1.88 or newer (edition 2024) and works on Linux, macOS, and Windows.
</Aside>
