This tutorial walks you through your first `localizedir` enum, from an empty crate to locale-aware directory lookups that compile and run. You embed a small localized template tree for an auth feature and read files back out of it in three languages.

## Prerequisites

- Rust **1.88** or newer (`rustc --version` to check)
- A terminal with `cargo` on your `PATH`

## 1. Create a crate

Start from a fresh binary crate:

```bash
cargo new demo && cd demo
```

## 2. Prepare the localized directory tree

`localizedir` expects a base directory that contains one subdirectory per locale. Inside each locale sit the parent folder (in this tutorial, `auth`) and one directory per enum variant. Create this tree next to your `Cargo.toml`:

<FileTree>
- tests/fixtures/localized/
  - **de/**
    - auth/
      - welcome/
        - note.txt
      - forgot_password/
        - note.txt
  - **en/**
    - auth/
      - welcome/
        - note.txt
      - forgot_password/
        - note.txt
  - **fr/**
    - auth/
      - welcome/
        - note.txt
      - forgot_password/
        - note.txt
</FileTree>

Put distinguishable content in each file — for example `en:auth:welcome` in `en/auth/welcome/note.txt`. The first path segment under the base path (`de`, `en`, `fr`) becomes a locale; the macro discovers them by scanning the filesystem at compile time.

## 3. Add the dependencies

<Tabs>
  <TabItem label="cargo add">
    ```bash
    cargo add localizedir@0.2 include_dir@0.7
    ```
  </TabItem>
  <TabItem label="Cargo.toml">
    ```toml
    [dependencies]
    localizedir = "0.2"
    include_dir = "0.7"
    ```
  </TabItem>
</Tabs>

<Aside type="caution">
You need both crates. The macro expands to `include_dir::include_dir!(...)`, which resolves in *your* crate, so `include_dir` must be a direct dependency.
</Aside>

## 4. Annotate an enum

Replace `src/main.rs` with:

```rust
use localizedir::{LocalizeDir, localizedir};

#[localizedir("tests/fixtures/localized")]
enum AuthDirs {
    Welcome,
    ForgotPassword,
}

fn main() {
    // Look up the embedded directory for one locale and variant.
    let dir = AuthDirs::Welcome.to_localized_dir("fr");
    let note = dir
        .get_file(AuthDirs::Welcome.full_path("fr").join("note.txt"))
        .expect("note.txt is embedded");
    println!("fr welcome note: {}", String::from_utf8_lossy(note.contents()));

    // Compile-time metadata: no runtime scanning anywhere.
    println!("locales: {:?}", AuthDirs::available_locales());
    println!("parent folder: {}", AuthDirs::parent_folder());
    println!("welcome dir name: {}", AuthDirs::Welcome.dir_name());
}
```

The attribute consumes the enum, re-emits it, and generates the `LocalizeDir` implementation. `AuthDirs` keeps working as a plain enum in every other respect.

## 5. Run and verify

```bash
cargo run
```

You should see output like this (locale order comes from the filesystem scan and is always sorted):

```ansi
[1m[32m   Compiling[0m demo v0.1.0 (/path/to/demo)
[1m[32m    Running[0m `target/debug/demo`
fr welcome note: fr:auth:welcome
locales: ["de", "en", "fr"]
parent folder: auth
welcome dir name: welcome
```

Break something on purpose to see the compile-time guarantee: delete `fr/auth/forgot_password/` and run `cargo run` again. The build now fails with a message listing every missing `(locale, variant)` directory and pointing at the attribute. Restore the directory when you are done.

## What you learned

- The base path in the attribute is resolved relative to your crate's manifest directory.
- Locale subdirectories are discovered at compile time and exposed through `available_locales()`, `has_locale()`, and the lookups.
- Embedded lookups return the real [include_dir](https://docs.rs/include_dir) `Dir`, so `get_file`, `files()`, and friends all work.
